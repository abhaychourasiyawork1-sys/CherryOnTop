Which screen layout feels right?

Both are real terminal-app patterns. Mockups below use monospace + box-drawing to show the actual feel, not a web UI.

A — Drill-down (k9s-style)
 org  ›  tree                                    [?] help  [q] quit
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 ● a3f1  DELEGATE      Implement OAuth login...
   ├─ ✓ e5a2  COMPLETE    Backend: token refresh
   └─ ● d57c  EXECUTION_DECISION  Frontend: login UI
                                             ↑ selected (enter to drill in)

 [enter] open node   [n] new run   [a] approvals   [/] search

Press Enter on a node → the whole screen becomes that node's detail (state, decision, live log). Press Esc to go back up. One thing on screen at a time, always full width.

B — Multi-pane (always-visible)
 TREE────────────────┬ NODE d57c ─────────────────────────
 ● a3f1 DELEGATE     │ state: EXECUTION_DECISION
 ├✓ e5a2 COMPLETE     │ decision: scoring...
 └●d57c EXEC_DECISION │   estimatedValue 1.2
                      │   modelCost      0.30
                      ├──────────────────────────────────
                      │ LIVE OUTPUT
                      │ ▸ reading src/auth/login.tsx
                      │ ▸ editing... ▌
 [tab] switch pane    │

Tree, selected node's detail, and its live output all visible at once, always. Tab moves focus between panes; the tree pane shrinks but never disappears.
