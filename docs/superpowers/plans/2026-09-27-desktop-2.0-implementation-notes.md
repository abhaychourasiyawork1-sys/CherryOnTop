## Mental model as built

- **Workspace = a repository.** The runtime already records the repository on
  every root node, so a Workspace is a projection (`lib/workspaces.ts`) and not a
  new store. Per-run benchmark worktrees (`<repo>/.bench/worktrees/*`) fold into
  their repository; a named branch worktree (`<repo>/.worktrees/<name>`) stays its
  own Workspace. Where new work goes is explicit: inside a Workspace it is that
  Workspace; on Home the composer carries a **"Work in ⌄" picker** listing every
  Workspace plus **"Open a folder…"** (native folder dialog in Electron, path
  entry in a browser). The daemon decides whether a folder is usable
  (`daemon.resolveRepo`: must be a git repository under the sandbox's home
  mount) and the window shows its reason when it is not. Opening a folder is how
  a new Workspace is created; it is remembered locally until its first run
  makes it part of the record.
- **Conversation = the Workspace's runs, oldest first.** Each thing asked is one
  exchange: the request, then a live run line, a compact result, or a failure
  with its next step. Questions answered from the record sit under the run they
  were about.
- **Files, Plan, Memory are surfaces, not places.** They open beside the
  conversation, which is what keeps conversation primary.
- **Organization (Decisions, Runs, Agents, Evidence) is revealed contextually** —
  only once a Workspace has delegation or more than one agent.

## Deliberate deviations and improvements

1. **Workspace is a projection, not a table** (tasks 1, 3, 4). The plan says the
   user creates or accepts a Workspace. With a repository-scoped daemon that is
   what opening the app in a repository already is; a Workspace table would be a
   second truth for the Desktop to reconcile, which the plan's own sync rules
   forbid. Revisit if a Workspace ever needs to span repositories.
2. **Surface kinds extended** with `files`, `memory` and `run` (task 1). Files and
   Memory needed to be surfaces to keep the conversation primary; `run` is the
   full working of one run beside the conversation.
3. **Decisions pair records with receipts** (task 13). The runtime writes a scored
   staffing row *and* an engine receipt for the same choice. Shown separately,
   one had a score and no reason, the other a reason and no score. They are now
   one decision with the receipt's reason and alternatives.
4. **Confidence is capped by evidence, visibly** (task 13): no evidence → *Not
   verified*; no passing verification → at most *Medium*; only failed checks →
   *Low*. The Deep Dive says when the engine's number was lowered.
5. **Attention classes** (task 14): approval and daemon-interrupted work are
   *Attention*; over-budget, gone-quiet, unmet checks and refused tools are
   *Inform*. On the live data this turned "17 need you" into "3 things need your
   attention". Approvals are never merged (one click must not answer two).
6. **Accountable revert is a new run** (task 19). It is created with a goal that
   names the original run and the files it changed, under the current mandate,
   and tells the agent to stop and report on conflict. The original run is
   untouched. A byte-level git revert would need runtime support for per-run
   commits and is not assumed.
7. **Redirect = stop + new run that names the one it replaces** (task 7). The
   runtime has no "change instructions mid-run"; this keeps the redirect on the
   record instead of pretending the old run was edited.
8. **Branches are local UI state** (task 8, marked `ponytail:`). The runtime has
   no conversation store. Runs, decisions, artifacts and memory stay Workspace-
   level; a branch only records where a run was asked. Branch conflicts are
   computed from files changed by runs in different conversations and appear in
   Attention as a decision for a person. Automatic branch *suggestion* is not
   built: there is no reliable signal for "the topic diverged" without a model
   call, and a wrong suggestion is worse than none.
9. **Plan controls follow what the runtime supports** (task 10): stopping a piece
   (recorded cancel) is offered; reorder and pause are not shown, because the
   runtime has no ordering or pause API and a control that does nothing is worse
   than none. Natural-language changes go through the composer.
10. **Details is paged, not virtualized** (tasks 12, 23, `ponytail:`). 200 rows
    per page, newest first.
11. **Palette indexes Workspaces, runs and actions** (task 20). Files, decisions
    and memory are reachable from their surfaces but not yet indexed — they need
    a daemon read per run; add a daemon search endpoint rather than fan-out.
12. **Capability discovery needs a daemon restart to appear.** A daemon started
    before this branch has no `daemon.capabilities`; the Deep Dive then shows the
    recorded judgments without annotating them, rather than failing.

## Not covered

- Automated end-to-end flows (task 24) — there is no browser automation in this
  repository; flows were exercised by hand against a live daemon.
- Starting new runs was not exercised during verification, to avoid spending the
  owner's model budget; the create path is the existing `node.create` call.

## Agent capabilities (web, git, GitHub) — measured in a real sandbox pod

| Capability | Before | After |
|---|---|---|
| Web search/fetch | Default mandate had neither tool; DNS in the sandbox timed out (CoreDNS → Docker DNS → host stub resolver) | WebSearch + WebFetch in every built-in (unedited tool lists move forward); CoreDNS forwards to 8.8.8.8/1.1.1.1 (`ORG_SANDBOX_DNS=host` opts out); jobs use `ndots:1` — 40/40 lookups ≤0.1 s |
| git commit | Failed: no identity | Your git name/email passed per run |
| SSH remotes | Port 22 closed | `git@github.com:` rewritten to HTTPS |
| GitHub (push, PRs, issues) | No `gh`, no token | Mandate capability `GitHub` (explicit only — an unrestricted grant does not carry it); token read fresh from `gh auth token` into the run's ephemeral secret; `gh` in the runner image; built-in **Ship** mandate |

Verified in a pod from the runner image under the runtime's egress policy: `gh` authenticated, `gh api user`, private repo cloned from an SSH-style URL, push dry-run accepted, commit attributed, HTTPS fetch 200.

**Open security finding:** the kind cluster's CNI (kindnet `v20250512`) does not enforce NetworkPolicies — a sandbox pod reaches the Kubernetes API and the LAN whether or not an allow policy selects it. The authority envelope's "never a private address" line is the design, not the current reality, until this is fixed (tracked as a separate task, together with ~20 leaked per-node policies).

## Sessions and the mandate editor (2026-09-27, later)

- **Chat sessions are daemon records** (`sessions` table, `nodes.session_id`, migration 0010). A session is one conversation in one repository; its runs stay the record. The window-local conversation branches (`lib/conversations.ts`, ConversationSwitcher, branch conflicts) were removed — sessions replace them.
- **Session memory** (`src/db/queries/sessions.ts`): a root run in a session is handed the session so far at dispatch (execute and plan), shaped like OpenHands' condenser / aider's history summary — first turn verbatim, latest four verbatim, the middle one line each, 24k-char budget with the oldest verbatim turns condensed first. The recap is part of the result-cache key so a follow-up is never answered from another session. `session.memory` exposes the exact text; the Memory surface shows it. ponytail: mechanical compaction; an LLM rolling summary is the upgrade when sessions routinely exceed the budget.
- **Sidebar** lists Workspaces (folders) with their sessions nested, Codex/Claude style. Files, Plan, Memory and Organization moved to the session header and are scoped to the session by projecting it as a Workspace of its own (`scoped` in App.tsx).
- **Mandates page** (`view.name === 'mandates'`): capabilities as plain-language switches (read, change files, run commands, web, GitHub) over the raw tool list, extra tools by name, team size stepper, spend with presets, standing instructions as a list, live envelope beside the form, dirty state + Ctrl S, duplicate, default-for-new-work, reset/delete. Reached from the sidebar, the composer's mandate picker, Settings, Authority and the palette.
- Fixed a regression from 4cf63b1: a crashed attempt (no report) is retried again; only a finished report-only run is spared the proof pass.
