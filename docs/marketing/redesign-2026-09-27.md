# Landing page redesign — research, plan, critique (2026-09-27)

## 1. Research

### Reference: plasma.ai (inspected HTML + shipped CSS)
Plasma sells the same idea CherryOnTop does ("managing agents starts to look like running an
organization"), so its art direction maps directly onto our product.

| Trait | What plasma.ai does |
| --- | --- |
| Canvas | Near-black `#141416` / `#1b1b1e` surfaces, off-white `#fafafa` text, greys `#5c5c5c`/`#8d8d8d` |
| Type | `neue-haas-grotesk-display` for huge tight headlines with a hard line break ("Infrastructure for / intelligence at scale"); `IBM Plex Mono` for labels, numbers, logs |
| Accent | One signal colour (green `#3ecf4c`) used only for live/ok states |
| Principle cards | Each principle has a *live mini product UI* as art: budget tree (`Operator $300 → Product $100…`), node list with spend, log rows animating in (`@keyframes card-log-row`), flash highlights (`card-art-flash`) |
| Buttons | `.btn-plasma`: translucent gradient fill, 1px accent-tinted border, glow on hover, drifting background (`btn-plasma-drift`), rotating conic outline (`btn-pulse-orbit`) |
| Motion | CSS scroll-driven animations (`animation-timeline: scroll()`) for edge fades; restrained, purposeful |

### Industry patterns (2026)
Sources: saasframe.io "10 SaaS landing page trends for 2026", vezadigital.com SaaS examples 2026,
landdding.com UI trends 2026.
- Dark-by-default with **one** neon accent (Linear purple, Raycast red, Mercury lime) — ours is cherry.
- Bento grids of modular cards with hover micro-interactions.
- Live product UI with agents doing work in the first five seconds of the hero.
- Motion that carries meaning, not noise.

### Technology choices (open source, widely adopted, zero new runtime JS)
- **Fonts:** Geist Sans (OFL-1.1, by Vercel) is the closest open-source analogue of Neue Haas
  Grotesk Display; IBM Plex Mono (OFL-1.1) is exactly what Plasma uses. Both self-hosted through
  `@fontsource` packages, because production CSP is `font-src 'self'` (a Google Fonts link would be blocked).
- **Motion:** native web platform features only — CSS keyframes, CSS scroll-driven animations
  (`animation-timeline: view()`, gated with `@supports`), IntersectionObserver, and one
  `<canvas>` 2D field. GSAP / three.js / Lenis were considered and rejected: they add bundle
  weight and have to be kept in sync with the existing reduced-motion and performance contracts,
  and this page needs none of their capabilities.

## 2. Design plan

Constraint: keep every section id, heading, copy string, ARIA contract and demo behaviour,
because 141 tests and the content policy depend on them. The redesign is visual and additive.

1. **Tokens:** Plasma-style neutrals, cherry as the single signal colour, verified green for OK
   states, Geist display type scale using `clamp()`, glass/border/glow tokens.
2. **Hero:** full-viewport. A decorative `PlasmaField` canvas (drifting agent-network nodes with
   cherry/rose glow) plus CSS aurora blobs and film grain. A huge two-line headline, still one
   `<h1>` with the same accessible name, with a staggered line reveal. Plasma-style gradient CTAs.
   On the right, a **live run console** (glass card) built from real demo data: goal, org
   tree with budgets, animated log rows, and the existing status indicator.
3. **Primitive marquee:** Goal · Organization · Mandate · Budget · Verification · Receipt ·
   Memory, running in mono type (`aria-hidden`, static under reduced motion).
4. **Video stage:** a device frame with a gradient border and glow. The frame tilts in 3D and
   flattens as it scrolls into view (scroll-driven; static fallback).
5. **Problem:** oversized statement, and the three questions as numbered 01/02/03 cards.
6. **Sections:** automatic mono index eyebrows (`01 /`) via CSS counters, large tight titles,
   glass cards with gradient hairline borders and a pointer-follow spotlight. Grid backdrop
   lines.
7. **Header:** floating pill nav with backdrop blur. **Footer:** a giant wordmark.

## 3. Critique of the plan (issues found and how they are resolved)

| # | Risk | Resolution |
| --- | --- | --- |
| 1 | Splitting the h1 into spans could change its accessible name | Spans are joined by a literal space, so the name stays "AI teams you can hold accountable." (tests query by name) |
| 2 | Google Fonts would break under CSP `font-src 'self'` | Self-host via `@fontsource` (bundled by Vite) |
| 3 | `animation-timeline` is unsupported in Firefox | Wrapped in `@supports`; the default state is the final, readable state |
| 4 | Canvas under jsdom / reduced motion / hidden tab wastes CPU or throws | Guard `getContext` returning null; draw one static frame under reduced motion; pause with IntersectionObserver + `visibilitychange`; cap DPR at 2 |
| 5 | The pointer spotlight could cost a React re-render per mouse move | One passive document listener writes CSS variables directly, with no React state |
| 6 | The marquee duplicates text for screen readers | The duplicated track is `aria-hidden` |
| 7 | The hero console's log rows could be read as real telemetry (content policy §3) | The card is labelled "Illustrative run" and only uses the existing deterministic demo data |
| 8 | Decorative layers could intercept clicks | `pointer-events: none` on every decorative layer |
| 9 | Contrast on glass cards | Text tokens stay ≥ 4.5:1 on `#0a0a0b`; glass alpha is kept low |
| 10 | Existing reduced-motion CSS contract test | Keep the global rule in `motion.css` unchanged |
